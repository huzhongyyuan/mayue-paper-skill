# 修改论文：先修论证，再修句子

适用：整稿审改、逐节重写、压页数、回应审稿意见。与 `writing-playbook.md` 配合；只读和当前章节有关的段落。以下是基于公开论文的迁移建议，不是作者私下编辑流程。

## 选择参照的依据

按问题结构选 1–3 篇，不按“都叫 Follow-Your”选。控制条件与数据不配对参照 Pose；独立因素和残留问题参照 Canvas；身份泄漏与局部监督参照 Emoji；新骨干上的旧假设参照 Motion；推理开销参照 FastVMT；在线时序参照 LiveLight。新增论文查 `corpus-2025-2026.md`。

用户给了草稿或工程就直接修改目标文件或返回可用修改稿。不要只交问题清单；不要把语言润色自动扩大成重跑研究。材料不足时完成可支持的部分，对影响结论的缺项精确标注。

## 逐段诊断的最小记录

| 字段 | 记录什么 |
|---|---|
| 位置 | 文件、节、段；避免编造不存在的行号 |
| 当前作用 | 任务定义、已知方法、失败、机制、操作、证据、边界、过渡中的哪一种 |
| 核心主张 | 一句可核查的命题 |
| 证据 | 对应代码、表图、实验设置或真实引用；没有则记待补 |
| 症结 | 原因没证据、术语变动、输入未定义、模块动机错配、对比不公平、重复等 |
| 处理 | 保留、重排、压缩、补定义、降强度、移附录；然后实际改写 |

小改动不必把表全部展示给用户。交付修改稿，加少量影响科学含义的改动说明即可。

## 各章节怎样改

**Title / Abstract。** 从已完成的主张反推标题；先核对任务、输入和约束，再压缩问题—机制—证据链。摘要不能引入正文没有的贡献。没有测延迟就写吞吐或运行时间；没有跨分布测试就不要写 generalizes broadly。标题品牌是可选的，不自动取 Follow-Your-X。

**Introduction。** 给每段起一个功能短名，把“已有进展→未解决条件→观察→解释→设计→证据”连接起来；该链是候选组织方式，缺少真实诊断时可用任务约束与设计推理，但不能加一句假的实验观察。“However”之前应当存在一个被转折的具体判断。贡献列表按可检验成果分组，避免把 backbone、缓存、loss 等全部凑成平行创新。

**Related Work。** 把罗列论文改成“谁依赖何种输入／表示／优化→在本文条件下哪条假设不适用”。修正误引和版本，保留最近且最接近的方法。不要以笼统的“cannot handle”替代实际比较。

**Formulation / Preliminaries。** 定义训练与推理分别能见到的输入、控制及不变量，清理符号冲突。只留后文需要的背景公式。检查目标视频、参考身份、目标姿态、未来控制是否被错误写成可用输入。

**Method overview。** 先写完整数据路径，再写阶段或模块划分；每个主要对象都应在图里找到。若实现是并行分支，不为了叙事写成先后两阶段。若模块只在训练用，不能在推理描述里让它继续参与计算。

**每个 Method 子节。** 用“目的／失败原因／输入／操作／输出与注入点／参数状态／验证”七项卡补缺项。不是七句固定模板：简单模块可用一段，复杂算法应分定义、操作、边界。新增公式必须描述真实运算；核查维度、求和集合、mask 方向、时间索引及梯度路径。

**Experiments。** 顺着主张组织比较、协议、主结果、消融与成本。每段先提出被检验的问题，再读数据，最后给范围有限的解释。移除模块同时减少计算量时，补算力相近的替代对照建议；不能据此直接宣布机制因果成立。把“training-free”与“no test-time optimization”分开。

**Limitations / Conclusion / Appendix。** 已观察失败和未测设置分开；结论只回收已有证据。附录承接实现、超参数、完整协议和补充结果，正文保留核心机制及决定主张可信度的设置。

## 整篇的一致性检查

沿同一个贡献 ID 检查 Abstract → Intro → Method → Figure label → Ablation。不同贡献不必同样长，但出现的名称不能飘移。沿同一个符号检查定义、公式、算法和图。结果表里的型号、分辨率、帧数、NFE、硬件、训练或优化条件必须能对上。

用户要求缩稿时，优先删重复背景、重复结果陈述和与核心方法无关的铺垫；保留必要定义、关键对照和主要限制。使用目标 venue 的真实规则决定页数；生成 TeX/PDF 时编译并看最终页面，检查浮动体、字号、跨页断句和图文距离。

## 原创编辑示例（虚构任务，不是实验事实）

原稿："Our powerful dual module greatly improves all aspects of video quality."

可支持的机制写法："The appearance branch supplies reference features to the denoiser, while the temporal branch propagates features across the current window. We evaluate their contributions to identity preservation and temporal consistency separately in [verified ablation reference]."

如果尚无该消融，末句改为实验计划或删去。例子的价值是拆开两项主张；不能用模板里的评价来代替用户的数据。

## 审稿意见模式

把意见落到具体命题和证据缺口，先核对原实验是否已回答，再安排最小补充分析。输出实际修订段落与 rebuttal 草稿，区分“已改”“已验证”“建议补做”。不把计划中的实验写成完成，不为修辞夸大显著性，不生成不存在的结果编号。
