## 08｜把学习结果转成你下一篇论文

### 8.1 从材料到完整稿的工作顺序

这是根据研究样本整理的建议流程，**不是对作者私下写作顺序的断言**。论文展示顺序也不等于实验发现顺序。

| 当前材料 | 先产出什么 | 达到什么条件再推进 |
|---|---|---|
| 只有方向 | 一句话任务、最近邻方法、失败假设、最小对照 | 能定义输入、输出、不变量与可反驳预测 |
| 有初步现象 | 动机实验协议和控制变量图草案 | 能区分候选原因，失败不依赖单一挑选样例 |
| 有机制与代码 | 模块卡、算法路径、训练／推理状态表 | 图中连接可回查实现，公式与张量可对应 |
| 有结果 | claim–evidence 表、主表、消融、失败与成本 | 摘要里的每项能力都有证据及范围 |
| 开始成稿 | 先写 Method / Experiments，再组织 Intro / Abstract | 每个模块由问题引出，每个主张有实验检验 |
| 有全文 | 逐节审查、图文对应、引用与排版 | 术语统一，强主张校准到数据，最终 PDF 可读 |

有现成稿时直接进入对应环节，无需机械地全部重做。论文的论证应忠于真实观察，不把事后合理化写成做过的因果实验。

### 8.2 给每一节建立“写前卡”和“写后检查”

| 章节 | 写前必须有的材料 | 写后读者应能回答 |
|---|---|---|
| Title | 输入／任务、贡献类型、条件 | 这篇解决什么，特点是什么？ |
| Abstract | 问题—操作—证据的压缩链 | 为什么需要，怎么做，证实了什么？ |
| Introduction | 最近邻、直接失败、诊断、贡献映射 | 为什么必须这样设计？ |
| Related Work | 按假设／机制分组的真实文献 | 和最近工作相同、不同、可比之处是什么？ |
| Formulation | 数据和控制的定义、训练／推理可见性 | 任务究竟允许获得哪些信息？ |
| Preliminaries | 后文会使用的公式与符号 | 阅读核心方法需要哪些共同概念？ |
| Method overview | 一条完整输入到输出路径 | 整体如何运行？ |
| 每个模块 | 七项模块卡：目的、原因、输入、操作、输出、训练、验证 | 为什么它必要，如何实现，如何检验？ |
| Experiments | 协议、日志、基线配置、消融、失败 | 比较公平吗，证据支持到哪里？ |
| Limitations | 设计假设、实测失败、未测范围 | 在什么条件下不应依赖该方法？ |
| Conclusion | 已验证贡献和边界 | 本文留下了哪项可靠认识或能力？ |
| Appendix | 可复现细节与正文指引 | 能否回查和重现关键结果？ |

### 8.3 一份可直接复制的项目工作表

```text
任务：给定什么，由用户控制什么，输出什么，必须保留什么？
目标设置：分辨率／序列长度／交互时机／资源预算。
最近邻：方法、版本、所需输入、训练和推理开销。
直接方案的失败：条件、样例 ID、可重复程度。
机制假设：为什么失败？还有什么替代解释？
诊断实验：改变什么、固定什么、观察什么、怎样推翻假设？
核心改动：输入 → 操作 → 输出 → 接入点。
参数状态：各阶段训练谁、冻结谁、推理保留谁。
主张：每项主张的结果文件、协议、比较与边界。
图表：动机 → 总图 → 模块图 → 主结果 → 消融／代价。
章节：每段一句功能描述；段尾如何引出下一段？
限制：已观察失败与尚未评测的设置分别记录。
```

### 8.4 怎样练到能自己写

1. **先做 Canvas 的反向提纲。** 暂时不看本手册，给 Introduction 每段写一个动词：定义、承认、诊断、分解、补足、验证。再与第 6 节对照，解释每次转折。
2. **做 Emoji 的模块压缩。** 将 landmarks 与 loss 各写成不超过一段的“问题→操作→位置→证据”；检查是否错误地把背景组件当创新。
3. **做 Motion 的跨章节连线。** 用两种颜色追踪主要问题如何出现在摘要、方法、图和消融中。标出没有对应的句子。
4. **用自己的结果重写一节。** 从 Method 子节开始，以真实输入输出与代码为依据。把每句标成目的、定义、操作、解释或证据，删除同义重复。
5. **换题检验迁移。** 去掉所有 Follow-Your 命名、手写字体与原作术语后，论证是否仍然成立？成立说明学到了组织方法。

评估自己是否掌握，可以用四个问题：别人是否能复述你的任务；能否从失败自然推出模块；能否照方法实现关键路径；能否从实验判断每项主张成立到什么程度。语言流畅和图好看不能替代这四项。

### 8.5 以后调用的具体示例

**从 idea 开始：**

> 使用 $mayue-paper-skill。我在做【任务】，观察到【失败】，可用资源是【数据／模型／算力】。请参考 Canvas／Motion 的问题推导方式，给出可反驳的假设、最小诊断实验、候选机制和章节骨架。不要把尚未验证的结果写成事实。

**从真实结果写章节：**

> 使用 $mayue-paper-skill。阅读【代码路径】【实验记录】【草稿】，先建立主张—证据表，再逐节写 Introduction、Related Work、Method、Experiments、Limitations、Conclusion。每个 Method 模块交代目的、输入输出、操作、训练与对应消融。缺失材料明确标注。

**审改现稿：**

> 使用 $mayue-paper-skill。逐段分析这份稿件：这段承担什么作用，是否有证据，如何接下一段；然后给出修改稿和改动理由。对照 Canvas／Emoji／Motion 选择合适的组织方式，不强行统一阶段数。

**画图：**

> 使用 $mayue-paper-skill。根据【已确认的方法说明】生成一张可编辑 SVG 框架图和一个模块放大图。先核对数据路径、冻结状态、训练专用分支和图注，再检查最终论文尺寸下的可读性。
